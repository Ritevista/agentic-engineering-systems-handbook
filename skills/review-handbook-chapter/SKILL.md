# Skill: review-handbook-chapter

## Name
review-handbook-chapter

## Description
Review a drafted chapter for technical clarity, consistency, practical value, and governance completeness.

## When to Use
- A chapter draft exists and needs quality review before merge.
- Terminology drift or case study drift is suspected.

## When Not to Use
- No chapter draft exists.
- Task is to create initial scaffold placeholders.

## Procedure
1. Read chapter and adjacent chapters for terminology consistency.
2. Check for practical architecture guidance over generic prose.
3. Validate Nexus case study continuity.
4. Evaluate examples, decision tables, anti-patterns, and verification guidance.
5. Produce prioritized, actionable feedback.

## Output Expectations
- Clear strengths and gaps.
- Ranked list of edits with rationale.
- Explicit terminology corrections.
- Merge readiness recommendation.

## Verification Checklist
- Feedback references specific sections.
- Terminology alignment checked.
- mdBook formatting concerns flagged.
- Missing verification guidance identified.
- Decision-table quality evaluated.
