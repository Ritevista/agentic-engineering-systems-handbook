# Skill: create-decision-table

## Name
create-decision-table

## Description
Create concise decision tables that help teams choose between adjacent agentic engineering patterns.

## When to Use
- A chapter needs operational decision guidance.
- Similar primitives could be confused in implementation.

## When Not to Use
- Narrative explanation alone is sufficient.
- Inputs are too vague to define clear decision criteria.

## Procedure
1. Identify the decision scope and options.
2. Define concrete criteria (risk, ownership, auditability, speed, blast radius).
3. Draft a Markdown table with recommendation guidance.
4. Add short notes for exceptions and escalation cases.
5. Link the table to Nexus case study usage.

## Output Expectations
- One mdBook-compatible Markdown decision table.
- Clear criteria and recommended option patterns.
- Practical notes for verification and governance.

## Verification Checklist
- Criteria are testable and unambiguous.
- Recommendation logic is clear.
- Table uses valid Markdown syntax.
- Verification implications are included.
- Terminology aligns with handbook definitions.
